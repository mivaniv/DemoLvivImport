# Lviv Import — демо B2B-каталогу

Next.js 16 + TypeScript + Tailwind CSS 4 + PostgreSQL 17 (Prisma 7). Дизайн — концепція «03 / Import Pro» ([docs/design/concept-03-import-pro.png](docs/design/concept-03-import-pro.png)).

Функціонально повторює чинний сайт lvivimport.com (B2B): ціни й замовлення бачать лише підтверджені клієнти.

**Зараз сайт працює як каталог без цін і входу.** Замість замовлення — кошик-заявка: товари додаються прямо з каталогу (ящиками), а заявка з контактами (ПІБ, телефон, email, коментар) йде менеджеру, доставку він узгоджує сам. Ціни, кабінет клієнта, реєстрація, кошик із цінами й прайс вмикаються перемикачем `NEXT_PUBLIC_B2B_ENABLED="1"` у `.env` (потім перезапуск або перезбірка), коли буде налаштовано пошту й ціни з 1С. Поки перемикач вимкнено, ціни бачить лише адміністратор (вхід — `/account/login`).

## Запуск локально

Потрібні Node.js 20.9+, Docker Desktop.

```powershell
npm install                 # також генерує Prisma Client
copy .env.example .env
npm run db:up               # PostgreSQL у Docker, порт 5433
npx prisma migrate deploy   # створює таблиці
npm run db:seed             # демоасортимент, демоціни, відгуки з lvivimport.com
npm run admin:create -- <email> "<пароль>"   # адміністратор (вхід через /account/login)
npm run dev                 # http://localhost:3000
```

Листи (заявки, замовлення, скидання пароля) без `SMTP_URL` зберігаються в `storage/mail/*.eml`.

## Сторінки

| Адреса | Що там |
| --- | --- |
| `/` | Банер, популярні позиції, новинки, акційні позиції, про нас, партнери, категорії |
| `/catalog`, `/promo`, `/new-products`, `/popular` | Пошук (назва, артикул, штрихкод), категорії, бренди, кількість у ящику, наявність, ціна (клієнтам); сортування як на lvivimport.com; по 12/24/48; «Завантажити ще» і сторінки |
| `/product/[slug]` | Позначки Top/New/Sale, артикул, штрихкод, «Від N шт», ціна за шт і ящик + кошик (клієнтам), «Завантажити прайс», «Отримати консультацію», вкладки «Опис/Характеристики», схожі позиції |
| `/about`, `/reviews`, `/contacts` | Тексти, клієнти, бренди, галерея; відгуки з модерацією й відповідями компанії; відділи, мапа, форма зворотного зв'язку |
| `/payment-and-delivery`, `/exchange-and-return`, `/terms-of-use`, `/privacy-policy` | Тексти з lvivimport.com |
| `/account` | Вхід, заявка на реєстрацію (менеджер підтверджує), відновлення пароля, мої замовлення, дані компанії, зміна пароля |
| `/cart` | Кошик і оформлення: власна логістика, Нова пошта, Делівері, Meest, самовивіз. Поки B2B вимкнено — кошик-заявка без цін: заявка з контактами (без доставки) йде менеджеру листом і в `/admin/inquiries` |
| `/price-list` | Прайс CSV для Excel (лише клієнтам) |
| `/admin` | Роль ADMIN: імпорт, клієнти (підтвердження/блокування), замовлення та статуси, звернення (дзвінки, форма контактів), модерація відгуків, позначки Top/New/Sale |

Шапка: телефон, графік, соцмережі, «Замовити дзвінок», кабінет, кошик. Підвал — як на lvivimport.com.

**Безпека:** паролі — scrypt; сесії в базі (cookie httpOnly, у базі лише SHA-256 токена); ціни не потрапляють у HTML і дані для гостей; обмеження частоти входу й форм; приманка для ботів.

## Імпорт з 1С

Дві задачі, обидві пишуть журнал (видно на `/admin`):

| Команда | Що робить |
| --- | --- |
| `npm run import:sync` | **Синхронізація.** Завантажує файл за `IMPORT_SOURCE_URL`, перевіряє, створює нові товари й оновлює наявні за ID з 1С. Категорії й фото (за посиланнями) беруться з файлу |
| `npm run import:cleanup` | **Прибирання.** Приховує товари, яких немає в останньому *повному* вивантаженні. Нічого не видаляє: товар, що знову з'явився у файлі, повертається автоматично |
| `npm run import:daily` | Синхронізація, а потім прибирання — лише якщо синхронізація успішна й файл містить увесь каталог. **Цю команду ставимо в cron** |

```bash
# crontab на сервері: щодня о 05:00
0 5 * * * cd /app && npm run import:daily >> storage/import.log 2>&1
```

Ручний імпорт файлу: `npm run import -- шлях/або/посилання`.

**Формати.** Визначаються за вмістом:
- **вивантаження lvivimport.com** (`<goods>`, повний каталог). Його ж щоранку імпортує чинний сайт, див. [docs/lvivimport-current-import.md](docs/lvivimport-current-import.md). Фото беруться з теки `images_backup/` поруч із файлом (усі фото товару). Тип ціни — `IMPORT_PRICE_TYPE` (номер `price_tier`, типово 1). Для локальної копії файлу теку фото задає `IMPORT_IMAGE_BASE_URL`;
- YML (`<yml_catalog>`, завжди повний каталог);
- CommerceML (`<КоммерческаяИнформация>`, повний, якщо `СодержитТолькоИзменения="false"`);
- нормалізований JSON ([src/importer/format.ts](src/importer/format.ts)).

Категорії показуються деревом: розділи 1С, а під відкритим розділом — його підкатегорії. Фільтр за розділом показує товари всіх його підкатегорій. Вага, фасування й бренд, які в 1С задані як довільні властивості, розпізнаються за назвами з [src/importer/mapping.ts](src/importer/mapping.ts).

**Запобіжники:**
- джерело недоступне, файл порожній або імпорт завершився з помилкою — прибирання не запускається;
- понад 20% некоректних товарів — каталог не змінюється;
- прибирання, яке приховало б понад `IMPORT_CLEANUP_MAX_RATIO` (30%) активних товарів, пропускається. Під час першого переходу з демоданих на реальні поріг можна разово підняти: `IMPORT_CLEANUP_MAX_RATIO=1 npm run import:cleanup`;
- зміни виконуються однією транзакцією; одночасно працює лише одна задача (`pg_try_advisory_xact_lock`);
- копії завантажених файлів (останні 14) лежать у `storage/imports`.

Тести: `npm test` (адаптери, паролі, повний цикл імпорту на окремій базі `lvivimport_test`). Приклади файлів — у [data/1c-sample/](data/1c-sample/).

## Хостинг HostPro (demo.lvivimport.com)

Після кожного push у `main` GitHub збирає сайт і **чекає підтвердження власника**, а тоді заливає його по FTP на demo.lvivimport.com. Налаштування й порядок підтвердження: [docs/hosting.md](docs/hosting.md). Поки на хостинг іде статична версія (каталог без цін), база не потрібна.

## Статична демоверсія (GitHub Pages)

Адреса: https://mivaniv.github.io/DemoLvivImport/

Workflow [.github/workflows/pages.yml](.github/workflows/pages.yml) збирає сайт після кожного push у `main`. База для цього не потрібна: дані беруться зі знімка [src/data/catalog-snapshot.json](src/data/catalog-snapshot.json).

Щоб оновити товари в демоверсії:

```powershell
npm run import -- шлях/до/вивантаження.json   # за потреби
npm run snapshot                                # усі активні товари (без цін) → src/data/catalog-snapshot.json
# npm run snapshot -- --limit 50                # або лише перші N товарів
git add -A; git commit -m "Update catalog snapshot"; git push
```

Чим статична версія відрізняється від повної (`NEXT_PUBLIC_STATIC_EXPORT=1` у [next.config.ts](next.config.ts)):

- модулі `*.static.ts(x)` підміняють роботу з базою; фільтри й пошук каталогу виконуються в браузері;
- файли `*.server.ts(x)` (адмінпанель, `/media`, захист паролем) до збірки не входять;
- відвідувач завжди гість: цін і кабінету немає (у знімку цін немає);
- кошик-заявка живе в браузері (localStorage, [src/lib/request-cart.ts](src/lib/request-cart.ts)): товари додаються з каталогу, кількість — ящиками;
- форми й заявка надсилаються на PHP-обробник хостингу ([deploy/hosting/api/form.php](deploy/hosting/api/form.php)), адреса — `NEXT_PUBLIC_FORM_ENDPOINT`. Без неї (GitHub Pages) форми пропонують зателефонувати;
- `page.static.tsx` замінюють сторінки кабінету поясненням.

Локальна перевірка: `npm run build:static`, результат у теці `out/`.
